## 本次修正

- 验收驱动原来只拒绝 timeout，failed/partial/cancelled 也会 exit=0。现在要求根任务和全部子任务 done、追加指令全部投递，并可指定必须实际出现的事件；deps 场景要求 continued，提问要求 ask/answer，定向返工要求 check.bounced。
- 真实复测发现 `after:[续派消息ID]` 不被识别，与“可引用前面的 SA_SEND ID”的契约不一致。已增加成功续派别名解析，必须匹配同源 note 与 continued 双回执，保留本工单、直接子任务、阶段边界及重放限制；同轮同键冲突明确拒绝。单元与集成回归覆盖等待续做结果、流式/终稿重放、普通留言不可冒充续派，并经独立静态审查。该解析修复尚未再发起一整轮计费模型验收。
- 每次使用新项目与新工单库；已有目录拒绝覆盖。未配置答案的提问停止测试，不自动编造答案。结束或异常会关闭执行器。
- 续派引导明确只接受 id、continue、body，继承既有权限与路由；要在续派后复审，应新建 after 依赖审查任务，不能给 continue 混入 write 或 after。平台权限与控制校验规则未放宽。
- 新增只读账本分析器，区分平台轮次、原生结果数、会话数及控制回执；AGY 累计用量按会话高水位聚合，未知值保留未知。新建脚本准备可复用的四类验收场景。
- 临时日志、提示、截图、账本及旧版备份不进入 Git，`tmpstate/` 已加入忽略列表。

控制拒绝会保留终稿及拒绝回执，不自动花费新一轮模型调用。普通工单在没有新任务等待时仍可能显示 done；因此 done 和模型自述均不能替代对实际控制事件及产物的核验。本次没有改变这一既有调度契约。
