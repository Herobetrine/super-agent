# 第一阶段：需求证据、交付快照与顾问用量

本文记录 2026-11-17 [长期架构设计](../architecture-evolution.md)第一轮开发包的实现边界。后续增量增加了[可选快照交付门](delivery-gate.md)和[操作员采用的快照行为检查](delivery-behavior.md)。目前纯文字需求也可以通过明确采用的行为检查取得证据。

## 操作入口

在 **项目面板 → 协作 → 需求与交付证据**：

1. 输入需求说明，可关联同一工单中的任务编号，点击“记录需求”。记录来源固定为操作员；尚未核查的要求显示“尚未验证”。
2. 对于事先明确目标字节的文件，可展开“文件验收标准”，填写项目相对路径和预期 SHA-256。大小写均可输入，保存时归一。不要把刚生成文件的摘要反过来当作独立验收标准。
3. 在“交付文件”中每行列一个项目相对路径，点击“捕获交付快照”。只捕获工单原项目 `tickets.cwd` 的明确清单；关联任务只是导航，不切换到协作者 worktree。
4. 查看文件标准符合、不符、未知或过期。点“修订需求”追加新版本；整个合同版本参与比较，旧界面的保存或捕获不能覆盖较新的修订。
5. 文件变化后点“刷新交付证据”重新核对。显示的是最近一次核对结果，不是持续监视文件的实时保证。

只读观察窗口能查看及刷新，不能修订或捕获。读取在后台执行，不启动模型或检查命令。首次打开、用户刷新和本窗口变更完成后读取，不在每帧重新扫描全部文件。保存异步完成后清除过期读取；切换工单不会把迟到回执应用到另一张工单。

## 证据含义与边界

`pass` 仅表示预先配置的文件 SHA-256 与快照字节一致，界面称为“文件指纹符合标准”。它不表示功能正确、用户接受、代码已合入或已经发布。没有文件标准的纯文字需求始终 unknown；模型的 `SA_REPORT done` 不会让它通过。

需求采用追加修订和合同版本 CAS；修订后的当前证据为 stale。快照冻结需求版本、预期标准、文件清单和字节对象，历史评测不读取后来改变的项目文件。读侧验证对象摘要并重新计算证据，不信任清单里保存的 `status`。

文件对象先写临时文件、核验并原子发布，再以事务关联快照。数据库锁内不读取大文件。失败可能留下未被引用的对象；对象后续丢失或损坏时，相关证据降为 unknown。没有引用计数清理器，当前不会自动回收这些对象。

损坏的最新清单会显示警告和未知证据，仍允许修订需求或重新捕获。需求保存返回同一提交事务中的结果，不会因提交后的证据读取失败而误报“未保存”。重新捕获遇到受控对象目录内可稳定读取、无链接且体积未超限的坏对象，会先在 `quarantine` 保留坏字节，再原子替换为已核验的正确字节；忙、权限、链接或超限错误不会被当作可修复损坏。Windows 替换前必须释放目标守护句柄，此顺序已用真实临时文件验证。

捕获对每个文件做有界读取和稳定性核对，再复读选定清单；这不是整个仓库的原子时点快照。当前没有将真实测试命令及其输入环境绑定到该清单，不能用它声称测试证据已经覆盖任意后续代码。

限制：每工单最多 256 项需求；每次最多 128 个文件，单文件 4 MiB、合计 64 MiB，清单最多 2 MiB。拒绝路径逃逸、Windows 设备名和备用流、Git 管理目录、链接及重解析点。现阶段也保守拒绝位于 junction 祖先下的路径。摘要查看使用共享读取，避免为了显示证据而阻止 agent 写文件；无法稳定核查时保持过期或未知。

尚未实现：自动提取和更新需求、执行者协议绑定、行为/界面验证器、自动执行完成门、任务工作区捕获、跨需求精确失效、整个仓库原子快照及存储回收。显式快照交付门、必需/可选/撤销范围及版本化核验见后续文档。

## 顾问用量

`advice.started` 的事件序号形成 `advice:<seq>` 调用身份，`usage.observed` 只保存必要的数值和去重身份，不保存顾问原生工具参数或完整原生内容；已有建议正文仍保留在 `advice.result`。

用量面板总量包含顾问，悬停可以查看独立顾问明细及已报告/未报告次数。调用者自己的 `JobUsage` 保持独立。累计值、结果更正和重复帧沿用各执行端的归一化规则；发现可观测原生累计身份与调用者或另一顾问重叠时保守标记缺口，不重复合计。

成功、失败、取消及超时均收取已排队的计量尾帧。单条计量写入失败不会丢弃已经得到的建议；`usage_complete=false` 使统计为 partial。最终建议回执无法保存时仍报错，不伪装成可靠交付。顾问取消使用子令牌，不反向取消调用者。生产时限仍为 14 分钟。

旧账本中的顾问调用缺少用量会显示未报告，使原本看似完整的历史总量降为 partial。这是覆盖口径更准确，不代表历史调用突然增加消费。执行端未暴露的内部调用、ACP 图片用量等仍可能未知；没有据此生成可信货币账单。

## 历史评测

原命令继续检查评测时的当前工作区；新增 `--snapshot ID` 明确选择同工单历史文件清单：

```powershell
./scripts/cargo.cmd run -p sa-store --example evaluate -- --data C:/path/to/disposable-ledger --ticket 1 --snapshot 1 --dataset dataset.json --case case-a --output snapshot-report.json
```

快照和日志在同一个只读事务中读取。文件摘要断言使用已核验对象；未列出、缺失或损坏的文件为 unknown，不回退当前工作区。有限清单不能证明文件不存在，因此快照来源下的 `workspace_file_absent` 为 unknown。跨工单快照拒绝。

只有文件断言选择历史来源。根任务状态、终稿、失败数、耗时与用量仍是报告 `through_event` 截止的当前日志；`journal_scope` 明确标注，不冒充快照捕获时的工单状态。

报告保存来源种类、快照 ID 和可信清单摘要。比较拒绝混用当前工作区与历史快照；同类来源允许比较不同快照 ID。新报告记录 `usage_rules_version=2`，旧报告缺该字段时按 1 解释；用量口径不同时 Token 差值为未知。缺失 Token/金额仍不能按零处理。顾问自定义执行端名与普通任务一样脱敏为 `other`，原生会话身份不进入报告。

## 验证入口

相关自动测试：`sa-engine --test delivery`、`sa-store --test delivery`、`sa-engine --test advice_usage`、`sa-store --test usage`、`sa-store --test evaluation`，桌面 `delivery_` 测试使用真实 App 与临时账本，执行记录、捕获、修订和只读观察。

`SA_LIVE_ADVISOR=<scenario.json>` 显式启用 `sa-adapters --test advisor_live`，运行真实只读顾问。配置包含 project、全新且位于项目外的 ledger、精确 model、brief，可选 provider。调用方是合成任务，不启动主控模型；只有 `Engine::consult` 调用真实模型，验证建议非空、独立用量有记录、总量没有重复加入。真实调用会收费，未设置开关时测试跳过，不能当作真实调用通过。

本机本轮日志、Fable 审查和验证回执在 `tmpstate/evolution-p0/`。具体全量、真实运行、发布及人工验收状态见[验证记录](../verification.md)，不能从本说明推断全部长期架构已实现。
