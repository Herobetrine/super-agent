# 工作目录自动准备 Git

工作台负责执行准备步骤，不依赖模型自行运行命令。新工单在目录、附件及扩展验证后、创建账本记录前准备；旧工单在实际执行轮次前准备。启动应用及只读观察历史工单不会批量初始化旧目录。Git 子进程在数据库事务外执行。

## 行为

- 无仓库目录：执行 `git init`，将未被 Git 忽略规则排除的现有文件保存为本地初始提交。遵守现有 `.gitignore`、全局忽略规则及仓库排除规则，不使用强制添加，不生成或覆盖项目忽略文件。
- 空目录：创建允许空内容的初始提交，使隔离工作区可以使用 HEAD。
- 已初始化但确实尚无提交历史的仓库根目录：补建初始提交。已有历史但当前 HEAD 无法解析时停止，不将其误当成全新仓库提交现有修改。
- 已有提交的仓库：复用原历史及分支，不自动暂存或提交后来的改动。隔离队列仍要求源目录干净。
- 已有仓库内的子目录：复用祖先仓库，不创建嵌套 `.git`、不改变所选工作目录。隔离写任务仍须选择仓库根目录；本次没有扩大任务目录或重写附件、MCP 范围。
- 损坏仓库、裸仓库、缺少 Git 或文件系统拒绝访问：明确报错，保留现状，不以重新初始化掩盖错误。

平台准备独立于模型权限：只读任务也获得初始 Git 基线，但原执行端权限不因此变为可写。新建初始提交使用命令级 Super Agent 身份，不修改全局 Git 设置。不会添加远端、推送、重置、清理或覆盖已有项目文件。

同一真实路径的准备通过操作系统文件锁串行，锁文件放在系统临时目录中，不进入项目基线。已有仓库的重复调用不增加提交。初始提交未完成时保留现场，后续重试可以继续准备；关闭或取消时终止所拥有的 Git 子进程。

同一引擎中的协作者复用已经成功准备的项目状态，避免大量协作者逐个启动 Git 探测。新建工单及主控后续轮次重新核验，重启引擎后重新准备；Git 元数据入口消失也会重新准备。这里复用的是仓库准备状态，不是工作树干净状态或检查通过回执，候选验证与确认仍执行原有核对。

成功完成准备并接受工单或执行轮次时，将本次初始化或初始提交的仓库根目录、是否初始化及初始提交 ID 写入 `project.git` 账本事件。模型的完成报告不能替代该回执；中途退出时仍需检查实际 Git 状态，不能假定文件系统与账本是同一个事务。
