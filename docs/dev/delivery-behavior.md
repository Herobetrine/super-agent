# 在交付快照上验证需求行为

协作页的「需求与交付证据」可以把某项需求、操作员采用的检查命令、测试定义及一次快照运行关联起来。通过回执回答的是“这些输入运行这条检查得到了什么结果”。一项需求同时声明文件摘要和行为检查时，两项都通过才满足需求。

## 操作步骤

1. 在项目的「完成检查」保存所需命令及参数。在需求卡片上采用其中一条。采用动作固定完整参数数组，并增加合同版本。之后编辑项目的默认命令不会替换已采用的标准。
2. 如果断言或预期结果来自项目文件，在采用时逐行填写这些文件。例如 `python -I -B check_total.py` 通常需要固定 `check_total.py`，脚本读取的参考结果也应列入。完整断言已写在参数中时可留空。
3. 捕获交付快照。清单应包含实现、固定的检查文件及运行所需的其他项目输入。一次运行的工作目录只用本次清单的文件创建。漏掉验证器或捕获到其他版本时，请核对清单。有意修改验收标准时，应重新采用。
4. 对该需求运行快照检查。展开回执查看快照编号、清单摘要、运行环境、退出码和输出末尾。需要中止时可点击「取消本次检查」。失败后根据输出区分断言失败与工具启动后的环境报错，再决定修正实现或调整检查。需求文字修订后，也需为新修订重新采用检查。
5. 启用快照交付核验后，可提交当前快照的整体结论。至少有一个有效必需项且全部必需标准满足，才能准备交付。重跑任一检查后需要重新核验。缺证和部分交付的原因可在协作页查看。
6. 操作员可以明确接受当前核验的快照，或在看到未满足项后接受这一次部分交付。接受记录指向具体核验回执。即使是同一个快照，重新核验也会产生新的回执号。旧接受记录仍可查看，新结论需要单独接受。

## 证据适用范围

| 观察到的情况 | 如何解读 |
| --- | --- |
| 检查正常退出、状态为通过 | 检查覆盖该工单、需求修订、采用版本及指定快照。检查覆盖哪些业务条件取决于所选断言。 |
| 检查正常运行但返回非零 | 该版本的命令执行失败。回执保留退出码和输出末尾，以便区分业务断言与工具报错。 |
| 中断、超时、验证器变化、输入在检查期间被改写、冻结对象缺损 | 该次尝试不能提供通过证据。重新运行会生成新的尝试编号。 |
| 执行中修订需求、重新捕获或启动更新的尝试 | 迟到结果不能更新当前版本的通过结论。已完成的旧回执有自己的身份。 |
| 项目在检查期间合入了新内容，或随后修改了清单里的文件 | 刷新后，当前项目输入过期，已保留的旧快照仍可独立核验。要交付新内容需重新捕获。 |
| 接受了部分交付 | 门仍显示部分符合，欠缺项继续列出。接受只覆盖操作员看到的回执及当时的未满足范围。 |
| 任务完成、候选合入、人工接受 | 可以分别查看任务状态、关联任务的合入轮次和具体快照的接受记录。 |

平台在临时目录中还原显式文件清单，执行前后逐文件核对。Windows 还会持有输入文件及目录句柄，直到检查进程树退出，防止运行中改写输入又恢复原字节。检查仍可新建输出文件。单次运行最长 10 分钟，回执最多保留合并输出的最后 4000 个原始字节。

运行使用本机操作员权限。工作目录、临时目录和用户目录单独创建，子进程只接收检查运行所需的环境变量。回执记录宿主平台、架构、执行器版本、实际启动的程序路径和摘要，以及搜索路径指纹。动态库、外部服务及命令主动访问的绝对路径仍依赖宿主。需要完整仓库或外部服务的检查，应先判断显式输入能否覆盖。项目中的断言脚本、参考结果及影响检查标准的配置应列为验证器文件。

执行器显式解析宿主程序路径，再设置检查工作目录。Rust 对相对程序路径配合 `current_dir` 的解析有平台差异。[Rust Command 文档](https://doc.rust-lang.org/std/process/struct.Command.html#method.current_dir)

Windows 的首个参数应为宿主 `.exe` 或 `.com` 的绝对路径，或宿主搜索路径中的程序名。脚本使用解释器作为首个参数，例如 `powershell.exe -NoProfile -File check.ps1`。仅有 `npm.cmd` 的配置、相对程序路径，以及默认依赖原用户目录中的 rustup 配置的命令，需要适配实际运行环境。验证器路径参与快照身份比较，捕获时应与采用时的拼写及大小写一致。

## 格式与复验

原文件快照继续使用清单格式 1。含有行为标准的快照使用格式 2。历史文件快照及旧库不会被补记为行为检查通过。已采用行为标准的工单应使用支持格式 2 的版本写入。回退程序应配合升级前的账本备份。

实际运行示例使用新建的合成账本和本机 Python 3。两个位置参数分别是尚不存在的绝对目录和 Python 可执行文件的绝对路径。

```powershell
$fixture = Join-Path (Resolve-Path tmpstate) ('behavior-' + [guid]::NewGuid())
$python = (Get-Command python.exe).Source
scripts\cargo.cmd run -p sa-engine --example delivery_behavior_demo -- "$fixture" "$python"
```

示例验证商品单价与数量求和，先运行错误实现，再捕获修复版本。模拟操作员明确接受第二份快照，随后修改当前项目并通过只读连接重开账本，核对接受仍指向原快照、当前文件已过期。自动回归使用 `sa-engine --test delivery_behavior`、两层原交付测试和桌面真实 App 测试。构建与运行结果见[验证记录](../verification.md)。
